\section{Rôle du service}

Les agents IA vivent dans le dépôt \repo{logiflow-ai-service} : une application \textbf{Flask~3}
(Python~3.13, Gunicorn), appelée \emph{uniquement} par Spring Boot. Le navigateur n'appelle jamais
ce service : Spring agit comme BFF et relaie notamment le flux SSE du copilote.

Quatre capacités sont exposées sous le préfixe \texttt{/internal/ai/v1} :

\begin{itemize}[leftmargin=*]
  \item \textbf{Copilote} --- conversations persistées, tool-calling vers Spring, RAG optionnel (pgvector), SSE ;
  \item \textbf{Planification} --- solveur déterministe de voyages + rédaction LLM ;
  \item \textbf{Maintenance prédictive} --- analyse déterministe (scores, anomalies) + synthèse LLM ;
  \item \textbf{Itinéraire} --- distance / durée / segments via \textbf{OSRM} uniquement \cite{osrm}.
\end{itemize}

\section{Principes de conception}

\begin{enumerate}[leftmargin=*]
  \item \textbf{Pas d'accès à la base TMS.} Planification, maintenance et itinéraire reçoivent tout le contexte dans le corps HTTP. Le copilote lit le métier uniquement via des \textbf{outils} Spring.
  \item \textbf{Base propre} \texttt{logiflow\_ai} (PostgreSQL + \textbf{pgvector}, schéma \texttt{copilote}) : conversations, messages, appels d'outils, feedback, fragments de connaissance.
  \item \textbf{Pas de JWT / Keycloak} dans Flask. Spring pose \texttt{X-Utilisateur-Id} et \texttt{X-Copilote-Contexte} pour les rappels d'outils.
  \item \textbf{LLM cloud compatible OpenAI} (Groq par défaut via \texttt{LLM\_BASE\_URL} / \texttt{LLM\_API\_KEY} / \texttt{LLM\_MODEL}). Un LLM local (Ollama) a été écarté : trop lent sur CPU pour le streaming \cite{groq,ollama}.
  \item \textbf{Calcul déterministe, LLM rédacteur.} Chiffres, horaires et scores ne dépendent jamais du LLM ; un gabarit texte prend le relais si le fournisseur est indisponible.
\end{enumerate}

\section{Séquence copilote}

Spring ouvre un flux SSE ; Flask charge l'historique, récupère le catalogue d'outils
(\texttt{GET /internal/copilote/outils}), boucle jusqu'à \texttt{COPILOTE\_MAX\_ITERATIONS\_OUTILS}
(défaut~4), exécute les outils via Spring (\texttt{POST /internal/copilote/outils/\{nom\}}),
puis streame les jetons. Événements SSE : \texttt{meta}, \texttt{attente}, \texttt{outil},
\texttt{token}, \texttt{sources}, \texttt{titre}, \texttt{fin}, \texttt{erreur}.

Outils métier typiques (Spring) : recherche dossiers / voyages / commandes / clients / chauffeurs,
proposition de voyages, consultation maintenance, consommation carburant. Outil local Flask
(si embeddings configurés) : \texttt{rechercher\_base\_connaissance}.

\figmmd{seq-copilote}{Séquence du copilote : Angular $\rightarrow$ Spring $\rightarrow$ Flask $\rightarrow$ outils Spring $\rightarrow$ LLM cloud (SSE).}

\section{Planification assistée}

Le solveur groupe les dossiers candidats, calcule une matrice de distances OSRM
(repli Haversine~$\times$~1,3), pose créneaux / pauses / équipage, puis le LLM rédige
justifications et comparaison (\texttt{source\_redaction}). Spring \textbf{réévalue la conformité}
avant restitution à l'UI ; la création du voyage reste une mutation TMS explicite.

\figmmd{seq-planification}{Séquence de planification assistée avec contrôle de conformité côté Spring.}

\section{Itinéraire et maintenance}

\begin{itemize}[leftmargin=*]
  \item \textbf{Itinéraire} : client OSRM HTTP ; réponse \textbf{503} si OSRM indisponible (aucun trajet inventé).
  \item \textbf{Maintenance} : score de risque, échéances de plans OT, anomalies (documents, sinistralité, surconsommation) calculés en déterministe ; le LLM synthétise ; gabarit si LLM down.
\end{itemize}

\section{Schéma de données copilote}

La base \texttt{logiflow\_ai} est distincte de la base TMS. Le schéma PostgreSQL \texttt{copilote}
est géré par Alembic (extension \texttt{vector}).

\figmmd{ia-schema}{Schéma relationnel du domaine copilote (conversations, messages, outils, RAG).}

\begin{itemize}[leftmargin=*]
  \item \texttt{conversation} --- fil de discussion par \texttt{utilisateur\_id} ;
  \item \texttt{message} --- rôles \texttt{user}/\texttt{assistant}, \texttt{sources} JSONB, tokens, modèle ;
  \item \texttt{appel\_outil} --- journal des tool-calls (nom, arguments, succès, durée) ;
  \item \texttt{feedback} --- note optionnelle sur un message ;
  \item \texttt{document\_connaissance} / \texttt{fragment\_connaissance} --- RAG avec colonne \texttt{embedding}.
\end{itemize}
